- Create procedure: in the hub, `cm find branch "where name='<branch>'" --nototal` printing nothing, then `cm branch create "br:<main branch>/<branch>"` (`<main branch>` is the main branch's full name, leading slash included, as `cm wi` in the hub reads it, such as `/main`; `<branch>` is the new branch's own name) and `cm workspace create <directory> "<path>" "rep:<repository>"` — `<directory>` the path's last component, and `<repository>` the repository `cm wi` names in the hub; then, in the new tree, `cm switch "br:<main branch>/<branch>"` — the create downloads nothing until the switch; where the project's verification needs files the branch does not control — private harnesses, local settings — the procedure may end with a seed: a step run from the hub that copies those files from the hub into the new tree and rewrites, in the copies, any literal hub path to the tree's; a seed is a branch tree's only — the WorktreeCreate hook, parked, would cut a writer tree from the branch alone, never seeded — and a seeded tree reads clean by the Clean read only where the project's `ignore.conf` ignores the seed's files, since `cm status --short --compact` lists every private file it does not ignore
- List read: `cm workspace list`, run as written from the hub or any tree — one line, a name and a path, for every workspace on the machine — kept to the hub's line and each workspace whose path lies under Location's directory, each with its branch by `cm wi "<path>"`, `<path>` that workspace's path as the list prints it, run as written from the hub or any tree, never wrapped in the Hub idiom — one line, `Branch <branch>@<repository>@<server>`
- Clean read: `py .claude/references/vc-plastic/clean-read.py "<path>"`, `<path>` the workspace's path in Windows form, run as written from the hub or any tree, never wrapped in the Hub idiom — it exits 0 with the lines of `cm status "<path>" --short --compact`, one per pending change or private file, minus each plain Changed file byte-identical to its base, and empty is clean; or it exits 1 with one `clean-read: …` line: the read did not complete, which is never clean
- Catch-up procedure: in the branch tree, which is clean, first the preview `cm merge "br:<main branch>" --machinereadable`, which changes nothing — a line not beginning `STATUS`, `FILE_SRC` or `APPLY` is a conflict, which stops with nothing to undo, and `STATUS ALREADY_CONNECTED` alone is nothing to bring in; otherwise `cm merge "br:<main branch>" --merge`, then `cm ci -c "<comment>" --all`; `cm undo -r .` undoes a merge left pending
- Remove procedure: `py .claude/references/vc-plastic/tree-remove.py "<path>"`, `<path>` the workspace's path in Windows form, run as written from the hub or any tree — one command, never wrapped in the Hub idiom: it refuses a path beneath no Location directory or not listed by `cm workspace list`, waits for the directory's release, refuses a workspace the Clean read does not read clean, with what it printed, and nothing changes; then it runs `cm workspace delete "<path>"`, which alone refuses nothing and leaves every file on disk, deletes the directory itself, reads back, and prints `removed`, `refused`, `absent`, `held` or `half-removed`; the branch is kept
