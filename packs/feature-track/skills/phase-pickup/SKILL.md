# phase-pickup

## What this is

**A phase pickup is orientation + reconnaissance + a plan that survives the session.** It turns "pick up phase N" into: verified current state, agent-gathered ground truth, a plan persisted into canon, and a validated go signal.

> Plan ONE phase. Recon by agents, and no plan exists until it is persisted in its own file beside the architecture doc.

## Bindings

- `process-docs` (required) — where the feature's requirements and architecture docs live, which the prerequisites confirm, and the path a phase's plan file is written at, which PERSIST fills. Absent → stop and say so before any recon is dispatched; the plan has no home, and an unpersisted plan does not exist. For a lite feature it also places the backlog whose row is read (`.claude/references/core/feature-lite.md` `## The acceptance source`).
- `vc` (required) — the working-tree read and the current branch at ORIENT and at the branch prerequisite (*Base-revision reads*), and the check-in at RECORD & COMMIT (*Check-in procedure*). Absent → stop and report; never improvise a version-control idiom.
- `board` (optional) — where cross-session state lives, the row ORIENT cross-checks against local state and RECORD & COMMIT advances. Absent → `memory/STATUS.md` is the state; orient from what the project binds instead, and skip the row advance.
- `layout` (optional) — the *Source*, *Tests* and *Generated* lines RECON quotes into the `code-mapper` dispatch, by which it classifies each site. Absent, empty, `TODO` or `none` → the dispatch says so, and `code-mapper` classifies each site by its own reading; never a stop.
- Agents — `architect` missing → stop before PERSIST and say so. `code-mapper` or `doc-extractor` missing → run RECON with what the remaining agent returns and record the gap in the persisted plan; both missing → stop, because the plan would rest on no verified ground truth. `code-mapper` missing with `doc-extractor` present → VALIDATE's brief says the report is missing, and the validator names check 1 and check 5's paired and generated files unchecked. `plan-validator` missing → the plan stop at PLAN always, PERSIST's brief asking the plan to record that it goes unvalidated, and VALIDATE skipped. `architect-reconcile` missing, or its row-brief dispatch returning other than `DONE` → the take stands, its record line's row update `not done — architect-reconcile missing` or `not done — architect-reconcile <its status word>`, no stop, and the next pickup takes the stale row's difference again.

## When it applies — and prerequisites

**Trigger:** starting or resuming an implementation phase on a feature branch.

The steps below branch on the four keys `## Bindings` above names — the process-doc layout, version control, whether a workflow board exists, and the project's source layout — and each carries its degradation path there.

Confirm before proceeding — if any item fails, stop and say which skill or step is actually needed:
- The feature branch exists and the workspace is on it (never plan on main).
- The feature's requirements doc and architecture doc exist (else: `feature-requirement-doc` / `architecture-doc` first). The skill applies the test of `.claude/references/core/feature-lite.md` `## The mark` here; a lite feature needs its architecture doc alone.
- The phase is identifiable from the architecture doc's Build plan (or the board row, where a board is bound).

A phase whose plan file exists at the path the `process-docs` binding names is planned: a resumed pickup goes to `implement` once the plan was validated — known by the `plan-validator` report `.scratch/plan-validator-<feature>-phase-<id>-report.md`, filed beside VALIDATE's brief; without one, to PLAN where the plan carries a `Scope:` line, a statement, take or ruling already given riding in the handoff brief, or a take its `PLAN take` line for this phase records in the session's dated note, and to VALIDATE where it carries none.

## Workflow

1. **ORIENT** — read the working tree and the current branch with the reads the `vc` binding's *Base-revision reads* slot names. If the project binds a workflow board, read it and cross-check the row against local state — if the row's stage, dates, or commit refs don't match (e.g. stage already `implement` with no matching workspace evidence, or notes newer than this session's handoff), state the mismatch and the reading this pickup follows — the local branch and files — go on, and list the mismatch at the next gate. No board bound → orient from the sources the project binds instead (e.g. open PRs/issues). Where this session ran the previous phase's `implement`, this pickup is a phase boundary: invoke `handoff`, its objective this phase's pickup, and take no further step, as `handoff` `## When to hand off` says.
2. **RECON** — spawn `code-mapper` (the code sites this phase touches and the files that change in pairs with, or are generated from, them, with any line refs from the docs to re-verify, and the `layout` binding's lines quoted verbatim, or a line saying it is absent) and `doc-extractor` (the requirements, ADR constraints, and architecture decisions bearing on this phase, as a numbered question list) — both in a single message, all paths absolute. For a lite feature the backlog row and the locked design stand for the requirements (`.claude/references/core/feature-lite.md` `## The acceptance source`).
3. **PERSIST** — scope is one phase: if the human asks for two, plan the first and note the second — never a combined plan. File `.scratch/architect-<feature>-phase-<id>-brief.md` on the field list of `.claude/references/core/brief-fields.md` — the phase and its scope, the phase's row in the architecture doc's `## Build plan`, quoted, the requirements and acceptance criteria it discharges, the architecture doc and the requirements doc by path, the two recon reports attached by path, the plan file's path — the pattern the `process-docs` binding names, `<feature>` and `<id>` filled — what is out of scope, and the project rules, as that field list says; it asks the plan to close with a `Runtime claims` list — each step whose correctness rests on what something does when run — or `none` — and, where `plan-validator` is not in the composed set, to record that it goes unvalidated; and dispatch `architect` in its plan mode through the Agent tool without a `name` to write the plan file at that path and its link line in the architecture doc's `## Build plan`. For a lite feature the brief says `lite`, gives the backlog's path, quotes the row and cites the criteria the phase discharges as A1…An (`.claude/references/core/feature-lite.md` `## The acceptance source`).
4. **PLAN** — read the persisted plan and compare it with its row by three triggers only: the files, the plan's files table against the files the row names, a file added or dropped — silent where the row names none; the scope, the plan's `Scope:` line against the row's scope, work taken on or dropped; the split, a Unit column in the files table where the row has no split. Never test counts, constants, step order or wording. A statement, take or ruling already given for this persisted plan, carried in the handoff brief, or a take a `PLAN take` line for this phase records in the dated note, ends the comparison, and PLAN goes on as that statement, take or ruling says. Three stops only: work the plan takes on in no build-plan row and no requirement → the no-row stop; a plan that needs a change to the architecture doc's seams or decision register → the reopen stop; `plan-validator` missing from the composed set → the plan stop. The no-row stop and the plan stop are each a ruling in session per `.claude/references/core/ruling-form.md`, its information the plan, the row and the PM's message naming what fired: the no-row stop's options drop the work by `architect`'s ruled-fix pass, or a scope change; the plan stop's, accept, recorded unvalidated, or stop for the composition. The reopen stop reopens the design question with the human, per the workflow, as RECONCILE's canon-conflict does — never patched around. A drop is `architect`'s ruled-fix pass: `.scratch/architect-<feature>-phase-<id>-fix-brief.md` in PERSIST's form, carrying the ruling and the plan file by its path, dispatched through the Agent tool without a `name`; PLAN then compares the rewritten plan. With no stop, or past the plan stop: a trigger fired → the plan is taken, stated in one message naming what fired and what was taken; none → state the plan in one message and go to VALIDATE. Where the take moves work to or from a later row, file `.scratch/architect-reconcile-<feature>-phase-<id>-row-brief.md` on the field list of `.claude/references/core/brief-fields.md` — the requirements doc, the architecture doc and the phase's recon reports by path, the take's record line through its `taken:` field, each later row concerned, quoted, with its edit worded (work taken on struck from its row; dropped work added to the next row, or, with none, a row appended before the first link line, the next free id, its *Discharges* that work's requirements), scope `## Build plan` rows only, and the project rules, as that field list says — and dispatch `architect-reconcile` in record mode through the Agent tool without a `name`, so the row stands updated before the next pickup; a take moving no work, or with `architect-reconcile` missing, files no brief. Each take is recorded, once any such dispatch returns, as one `## Decisions` line, `PLAN take — phase <id>; trigger <files | scope | split, each that fired>; taken: <work taken on or dropped>; row update: <row edited | Phase <n> appended | none | not done — architect-reconcile missing | not done — architect-reconcile <its status word>>`, in an entry appended to the session's dated note in `.claude/references/core/gate-close.md` `## The dated note`'s form, where the G2 packet's side-rulings sweep finds it (`.claude/references/core/gate-packet.md` `## The G2 packet`) — under a filled `trees`, one hub operation, `scripts/hub.py write` with `--note` (`.claude/references/core/trees-contract.md` `## The hub operation`); then go to VALIDATE. No step drafts a plan or enters Claude Code plan mode.
5. **VALIDATE** — pick the depth: `narrow` where PLAN's comparison fired no trigger and the plan's last line reads `Hazards: none`; otherwise `full`. A fired trigger gives `full` whatever ruling follows; a plan rewritten by the ruled-fix pass at the no-row stop is judged on its own comparison; on a resumed pickup a carried statement means none fired, a carried take or ruling that one did, and a pickup that reaches VALIDATE with no comparison run reads `full`. File `.scratch/plan-validator-<feature>-phase-<id>-brief.md` on the field list of `.claude/references/core/brief-fields.md` — the plan file by its path, the depth, the `code-mapper` report RECON returned, by the path PERSIST attached it at, as the validator's ground for the code, and the canon set (requirements, the architecture doc with its `## Decision register`, ADRs), the project rules, as that field list says, and nothing of this session's reasoning — and spawn `plan-validator` on that brief. The plan's runtime claims are not the validator's to confirm: they go to implement's first gate. For a lite feature the canon set is the backlog row, the locked design, the architecture doc and the ADRs, and the brief names the feature lite (`.claude/references/core/feature-lite.md` `## The acceptance source`).
6. **RECONCILE** — the PM rules which findings are real defects. A canon-conflict finding stops the line: per the workflow, reopen the design question with the human — do not patch around it. Findings ruled real in the other fix-pass classes `plan-validator`'s defect-class line names are applied by a second `architect` dispatch: `.scratch/architect-<feature>-phase-<id>-fix-brief.md` in PERSIST's own form, carrying those findings and the plan file by its path and nothing of the PM's reasoning, dispatched through the Agent tool without a `name`. Every other finding stays in the validator's report, for `implement`. If a defect changes the plan's scope, re-gate with the human. For a lite feature an `unfixed-choice` finding ruled real by the test of `.claude/references/core/feature-lite.md` `## The escape` is the return `.claude/references/core/feature-lite.md` `## The return to full` describes, not a fix pass.
7. **RECORD & COMMIT** — if a board is bound, advance its row (implement stage, date). Then check in per the `vc` binding's *Check-in procedure* slot. If the binding marks the process-doc area untracked/local-only, the persisted file is the record — nothing to commit.

A handoff taken at a step boundary, as `handoff` `## When to hand off` says, at the end of PLAN carries the plan file's path and the statement, the take with its record line, or the ruling, not the plan whole, so the next session's PLAN goes on from it. After step 7 there is no next step, and the objective is `implement` for the phase, as `handoff` `## When to hand off` says of a skill's last step.

Recon, the plan's authorship and its validation are the agents' work.

Inside skill work a turn ends on a stop line, its last line `Stop: <kind>` or `Stop: <kind> — <detail>`, the kinds and the `declared` detail as `.claude/references/core/hooks.md` `## What the stop-line hook passes` states; core's stop-line hook blocks any other end once.
